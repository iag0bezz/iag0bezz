Como eu trabalho

Menos código, menos superfície de bug

Prefiro a versão simples que funciona a uma abstração pronta para um requisito que talvez nunca apareça. Onde tem dado sensível ou dinheiro, o cuidado extra deixa de ser opcional.

1

Entende o problema

Antes de escrever qualquer linha, mapeio o que precisa existir de verdade. O que é especulativo fica de fora.

2

Arquiteta a solução

Stack e estrutura pensadas pra manutenção, não pra impressionar. Contratos claros entre as partes.

3

Constrói com testes

Onde importa segurança ou dado sensível, tem teste. O resto fica simples de propósito, sem cobertura fingida.

4

Documenta e entrega

README e deploy que não dependem de mim pra rodar de novo. Quem chegar depois entende sem perguntar.
